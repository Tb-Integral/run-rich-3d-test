# План реализации

## Порядок приёмки
Каждый этап: реализация → проверка агентом → ручная проверка пользователем → исправления → подтверждение → отдельный коммит и push. Следующий этап начинается по запросу. Инициализация репозитория — отдельная подготовительная операция.
Проверяем пока в Unity мышью. Целевой кадр портретный; видео 880×1920. Android и публикация игры в магазин не входят в текущую проверку. Срок сдачи не задан.

## 0. Подготовка (завершены настройка и техническая проверка)
- Правила, локальные скиллы и роли ревью, план, разбор исходного видео.
- Инвентаризация ассетов, диагностика и исправление блокирующих ошибок исходного кода.
- Проверки Unity, отчёт об оставшихся ограничениях; публичный GitHub с начальным состоянием.
- Готовность: проект компилируется, проверки выполнены или ограничения явно указаны; отсутствующие ассеты не скрыты.

## 1. Визуальная основа и персонаж (следующий этап, не начат)
- Создать редактируемую Gameplay-сцену, отдельную папку собственного проекта.
- Собрать первый прямой участок белой дорожки, воду, небо, освещение, тени, портретную камеру.
- Использовать подтверждённый FBX-скелет player и проверить пригодность мешей; собрать стартовый внешний вид, восстановить потерянные назначения текстур и подготовить совместимые URP-материалы. В поставке 42 материала без доступного шейдера.
- Восстановить/подобрать и ретаргетировать анимации: Unity подтвердила, что исходных клипов нет. Сначала проверить цикл ходьбы на месте. Не выдавать временную анимацию за копию.
- Приёмка: кадр старта сопоставим с видео, модель не розовая и не в T-позе, тени и масштаб согласованы. Это первый этап после подготовки.

## 2. Управление и движение
- Автоматическое движение вперёд, непрерывное горизонтальное перетаскивание мышью и поддержка touch тем же алгоритмом.
- Разделить измерение ввода и движение. Настроить нормализацию по ширине экрана, чувствительность, ограничения дорожки, поведение отпускания и повторного захвата.
- Проверить повороты трассы и поведение камеры; не заменять управление дискретными полосами.
- Приёмка: короткие/длинные движения, резкая смена направления, отпускание и повторный захват, края, 30/60/120 FPS, два портретных размера. Точные коэффициенты согласуются вручную; touch пока не проверен.

## 3. Цикл забега и стартовый UI
- Состояния Ready → Running → Finishing → Won/Lost; явные правила переходов.
- Подсказка с рукой и стрелками, старт первым жестом, номер уровня, текущий счёт, перезапуск.
- Подключить имеющийся Level Manager через небольшой слой управления забегом.
- Приёмка: до старта персонаж не бежит; после завершения ввод отключён; перезапуск очищает состояние. Временные отладочные способы завершения доступны только в Editor.

## 4. Деньги, алкоголь, шкала и смена внешнего вида
- Однократный подбор, рост/падение состояния, границы и пороги, подписи/цвета шкалы над головой.
- Смена костюма и анимационного состояния без смещения персонажа; цифры подбора и базовые эффекты.
- В видео используются пачки купюр, хотя задание называет их монетками. Визуальный источник — видео.
- Приёмка: подбор не дублируется, пороги корректны в обе стороны, рестарт возвращает исходный вид и баланс.

## 5. Первый уровень: маршрут, препятствия и выбор
- Собрать полный маршрут по таймкодам, повороты, расстановку купюр и бутылок.
- Области с флагами и ворота «Вечеринка / Школа», эффекты выбора и препятствия первого уровня.
- Назначение жёлтых областей уточнить по покадровому сравнению; не придумывать скрытые правила из скриншота.
- Приёмка: весь маршрут проходим, препятствия и зоны срабатывают один раз, выбор воспроизводит наблюдаемый результат.

## 6. Финиш, победа, поражение, следующий уровень
- Шахматная линия, финишная последовательность x2–x5, ограничения продвижения состоянием персонажа, финальная анимация.
- Экран победы и поражения, Retry и Next; следующий номер уровня с повторным использованием первого layout допустим.
- Поражение и непоказанные исходы оформить явно как согласованное поведение: в исходном видео есть только победный проход.
- Приёмка: победа → следующий старт → повторный забег; поражение → повтор; двойной клик не создаёт две копии; прогресс уровня сохраняется корректно.

## 7. Полишинг и сверка
- Анимации переходов, шаги, звуки, вспышки, купюры/красные частицы, плавность шкалы, UI и камера.
- Сопоставить ключевые кадры и длительность участка, скорректировать расхождения.
- Проверить Console, производительность и отсутствие заметных выделений памяти в частых действиях.
- Приёмка: визуальное сравнение пользователем; перечислены оставшиеся отличия, нет заявлений «1:1» без проверки.

## 8. Сдача
- Чистое открытие из GitHub, запуск по README, сборка выбранной платформы при необходимости.
- Финальное ревью кода и короткая инструкция проверяющему.
- Запись около 60 секунд: первый уровень, победа, переключение, начало повторного уровня; без редакторского интерфейса.
- Пользователь публикует ролик на YouTube, либо отдельно поручает публикацию через доступный аккаунт. Добавить реальную ссылку в README после получения.
- Приёмка: публичная ссылка GitHub и доступная ссылка YouTube, без заглушек.
